# M1.8-B2a validation: isolated kinematics sampler and ROOM mapping parameter

Status: **accepted and committed.** B2a is frozen; B2b adopts a profile-specific cap
architecture (section 8 alternative C-style separation), recorded in
[game/M1_8_B2B_CAPS.md](../../game/M1_8_B2B_CAPS.md).

Baseline: B1 accepted, committed and frozen at `8a8064da05a7fa8e561cf049b477f66e43e4266e`.
The accepted B1 resolver/profile/executor architecture was preserved, not reshaped.

**Headline result: still bit-identical.** All 7 deterministic scenarios and 4060 ticks
reproduce exactly, all pre-existing random streams end in identical states, and the new
kinematics stream is provably never drawn from. No tolerance was introduced.

B2a contains **no speed distributions**: no gamma, lognormal, normal, empirical
resampling, persistence draw or stochastic acceleration envelope exists. No
`room_kinematic_scale` value other than 1.0 was chosen. `max_speed` was not changed.

## 1. Sampler architecture

B1 established `KinematicResolver` as pure, stateless and RNG-free. That property is
preserved: the random stream went into a **separate** component rather than into the
resolver.

```text
behavioral / ecological context
  -> KinematicSampler    (owns the only kinematics RNG; may draw a context speed)
  -> KinematicResolver   (pure: request -> profile; no RNG, no mutable state)
  -> KinematicProfile
  -> KinematicExecutor
  -> WORLD physics
```

`World._move_fly` now reads:

```python
sampled = self.kinematic_sampler.target_speed_bl_s(command, threat_priority)
profile = self.kinematics.airborne(command, threat_priority, sampled)
```

`KinematicSampler.target_speed_bl_s` returns `None` on **every** call in B2a, and `None`
means "no sample taken; use the ecological command unchanged". The resolver's new
`sampled_speed_bl_s` parameter is an additive optional argument, so the B1 signature and
behavior are intact. B2b changes only the sampler's return value.

A test asserts the resolver still has no attribute whose name contains `rng` or
`sampler`, so the purity property cannot silently regress.

## 2. RNG offset and reset semantics

| Stream | Offset | Owner |
| --- | --- | --- |
| `world` | +0 | `World.rng` |
| `flight` | +3907 | `FreeFlightController` |
| `ecology` | +7013 | `EcologicalController` |
| `spawn` | +8191 | `World._spawn_rng` |
| `lifecycle` | +18001 | `LifecycleController` |
| **`kinematics`** | **+24593** | **`KinematicSampler`** (new) |

`KinematicSampler.SEED_OFFSET = 24593` is unique among these. A regression test asserts
the offsets are pairwise distinct **and** that each offset produces a distinct first draw
from the same base seed, so uniqueness is checked on behavior rather than on the literals
alone.

Reset semantics follow the established pattern: the sampler is constructed in
`World.__init__` and **reseeded in `World.reset(seed)`**, immediately after
`self.flight.reset(seed)`. Two tests cover this: reseeding from the same seed restores an
identical bit-generator state, and a different seed produces a different one. Without
this, restart determinism would break as soon as B2b starts drawing.

## 3. Proof that no random draw affects behavior

Three independent checks, not one:

1. **Machine-checkable inertness.** `KinematicSampler.untouched` is true only while
   `draws == 0` **and** the bit-generator state still equals the state captured at seed
   time. `tools/kinematics_trace.py` records this per scenario; it was `true` for all 7.
2. **Stream state in the trace.** The kinematics stream's final state is now captured
   alongside the others. Because no draw occurs, it remains at its initial seeded value
   for the entire run.
3. **Comparator enforcement.** `tools/kinematics_diff.py` now separates a stream that
   exists in both captures and *differs* (a failure) from a stream that is newly *added*
   (reported, not a failure), and raises a `kinematics_sampler_drew` finding if inertness
   is ever violated.

The comparator output:

```json
{"scenarios": 7, "total_ticks": 4060, "bit_identical": true,
 "existing_rng_streams_unchanged": true, "new_rng_streams": ["kinematics"],
 "kinematics_sampler_untouched": true, "findings": []}
```

## 4. `room_kinematic_scale`

| Property | Value |
| --- | --- |
| Location | `game_room_config.json` -> `kinematics.room_kinematic_scale` |
| Value | **1.0** (no-op; deliberately not chosen above or below 1.0) |
| Classification | **Class C** — simulator/environment mapping parameter |
| Applied at | exactly one site, `KinematicResolver.ecological_units` |
| Applies to | non-neural ecological locomotion only |
| Does **not** apply to | threat-priority cruise, landing approach, takeoff, escape impulse |
| Presets | absent from LAB and GAME, which default to 1.0 |

The conversion is `BL/s -> body length -> ROOM mapping -> world units/s`:

```python
def ecological_units(self, speed_bl_s):
    return speed_bl_s*self.body_length*self.room_kinematic_scale
```

It is **not** a measured biological constant, and no literature magnitude has been
adopted. The config `_comment` states this inline so the value cannot be misread later.

Two deliberate asymmetries, recorded rather than resolved:

- **Landing approach does not take the mapping.** `KinematicResolver.landing_approach`
  keeps the plain `bl_s * body_length` conversion, because landing speed belongs to the
  frozen M1.8-A lifecycle. At any scale other than 1.0 this becomes an inconsistency
  between ecological flight and landing approach. It is a B2b decision, flagged here.
- **`baseline_speed` does not take the mapping.** It is configured directly in world
  units/s (216), not BL/s, so there is no conversion site to apply it at.

### 4.1 Bit-identity of the trailing multiply

The instruction was to prove the `* 1.0` is exact in the real expression or keep the
parameter dormant. It is exact: for all finite IEEE-754 doubles `x * 1.0 == x`, so
`(bl_s * body_length) * 1.0` reproduces `bl_s * body_length` bit-for-bit. This was
verified empirically, not just argued — the post-B2a trace hashes are unchanged, and
`test_room_kinematic_scale_is_one_and_maps_exactly` asserts exact equality across
`0.0, 1.5, 6.0, 9.0, 13.0, 1e6` BL/s. A separate test builds a resolver at scale 2.5 to
prove the parameter is genuinely wired rather than dead code.

## 6. `max_speed` audit

Generated reproducibly by `tools/max_speed_audit.py`
(`artifacts/m1_8_b2a/max-speed-audit.json`). The tool changes nothing.

**Where it comes from.** `fly.max_speed = 1000.0` world units/s, present identically in
all three presets (`game_config.json`, `game_play_config.json`, `game_room_config.json`)
since the original game configuration. At `body_length_px = 24` that is **41.667 BL/s**.

**Classification.** The accepted M1.8-R0 parameter inventory already classifies it:
**C — "Physical speed cap, not a species flight maximum."** That classification is cited,
not re-derived.

**Every path that uses it**, measured rather than asserted:

| Path | Uses the cap | Currently binding |
| --- | --- | --- |
| Ordinary airborne ecological target | yes, `min(max_speed, ...)` | no at scale 1.0; verified reachable with an absurd command |
| Baseline / threat-priority cruise | yes, executor clamp with `clamp_speed=True` | no (216 units/s) |
| **Neural escape impulse** | **yes** — the impulse is added *before* the executor, which then clamps | **yes**: from 0.9x cap plus a full-strength impulse, post-tick speed is exactly the cap |
| Lifecycle voluntary takeoff | yes, `min(max_speed, 6 BL/s * body)` = 144 units/s | no |
| Lifecycle landing approach target | yes, `min(max_speed, ...)`; executor clamp is **off** | no (36 units/s at contact speed) |
| Recorder diagnostic | `speed_cap_exceeded` flag at `> max_speed + 1e-6` | tolerance needed because sideslip re-derives velocity after the clamp, leaving ~1e-13 of slack |

So the cap constrains **ordinary airborne ecological locomotion and neural escape**, and
merely bounds (without binding) the two lifecycle targets. That the escape path is capped
matters: it means `max_speed` is not a purely ecological knob and cannot be raised
without also widening the frozen M1.8-A escape envelope.

## 7. Saturation analysis

If `room_kinematic_scale` were raised while `max_speed` stayed at 41.667 BL/s, each
ecological band would begin truncating at these scales:

| Context | Envelope (BL/s) | Top touches cap at scale | Whole band saturated at scale |
| --- | --- | --- | --- |
| `TRANSIT` | 9-13 | **3.21** | 4.63 |
| `ODOR_TRACK` | 9-13 | **3.21** | 4.63 |
| `EXPLORE` | 5-8 | 5.21 | 8.33 |
| `RECOVER` | 5-8 | 5.21 | 8.33 |
| `ODOR_SEARCH` | 4-7 | 5.95 | 10.42 |
| `ALERT` (bypassed) | 8-12 | 3.47 | 5.21 |
| `ESCAPE` (bypassed) | 12-18 | 2.31 | 3.47 |
| `LAND_OR_PERCH` (legacy) | 1-3 | 13.89 | 41.67 |

The reviewed R0 references all exceed the cap in body-normalized terms:

| Reference | m/s | BL/s at 2.5 mm | 3 mm / 2 mm bracket | Exceeds 41.7 BL/s cap |
| --- | --- | --- | --- | --- |
| E03 steady groundspeed | 0.15-0.20 | 60-80 | 50 / 100 | yes |
| E02 intersaccadic | 0.267 / 0.381 | 107 / 152 | 89 / 191 | yes |
| E06 landing approach | 0.37 | 148 | 123 / 185 | yes |
| E05 airspeed near plume | 0.55-0.59 | 220-236 | 183 / 295 | yes |

**The saturation problem, stated plainly.** Reaching even the most conservative reference
(E03, 60-80 BL/s) from TRANSIT's 9-13 BL/s needs a scale near 6.5. At that scale
TRANSIT's entire band, EXPLORE's entire band and ODOR_SEARCH's upper half all sit above
the cap. Every affected context would collapse onto the *same* clamped value, so raising
the scale without addressing the cap would **destroy the context dependence B2b exists to
create**, while also silently widening the neural escape envelope. Truncation would be
invisible in the mean and obvious only in the distribution tail, which is exactly the
kind of artifact the B2b metrics must be able to see.

This is **not solved in B2a.** No cap value was changed.

## 8. B2b cap-design alternatives (not selected)

- **A. One engineering safety cap, explicitly raised and mapped.** Keep a single
  `max_speed`, but derive or raise it alongside the mapping so it stays a genuine safety
  bound rather than a behavioral shaper. Simplest; but because the escape path shares the
  cap, it changes the frozen M1.8-A escape envelope and would need re-acceptance.
- **B. Ecological cap scales with `room_kinematic_scale`.** The cap applied to ecological
  locomotion tracks the mapping, while the escape and lifecycle paths keep the present
  absolute ceiling. Preserves the M1.8-A freeze; introduces two different ceilings, which
  must be named and recorded distinctly to stay honest.
- **C. Context-specific distribution truncation plus a separate hard numerical ceiling.**
  Each context's distribution carries its own bounds (the existing inert
  `speed_envelope_bl_s` hook), with a high absolute ceiling retained purely as a
  numerical-safety guard that should never bind in normal play. Most expressive and the
  best fit for per-context evaluation; the most implementation work, and it needs an
  explicit test that the safety ceiling is genuinely non-binding.

**Decision taken after this report was written:** the shared `max_speed` will *not* be
raised. B2b adopts a profile-specific cap architecture that gives ecological locomotion
its own cap while the accepted neural escape envelope stays equivalent to today's
1000 units/s behavior, under a separate global numerical safety ceiling. See
[game/M1_8_B2B_CAPS.md](../../game/M1_8_B2B_CAPS.md). The final ecological cap value is
still unchosen.

## 9. Contexts: sampled later versus excluded

Declared in code as `SAMPLED_CONTEXTS`, `NEURAL_OVERRIDE_CONTEXTS` and
`LIFECYCLE_OWNED_CONTEXTS`, and asserted disjoint by test.

**Will eventually be sampled (B2b):** `EXPLORE`, `TRANSIT`, `ODOR_TRACK`, `ODOR_SEARCH`,
`RECOVER` (where appropriate).

**Excluded — neural override:** `ALERT`, `ESCAPE`. The validated arbitration stays
`Retina / MaleCNS -> neural Action -> threat-priority kinematics / escape impulse`.

> **The configured `ecology.speed_bl_s` ALERT (8-12 BL/s) and ESCAPE (12-18 BL/s)
> envelopes are currently non-authoritative and are bypassed whenever `threat_priority`
> holds** — that is, whenever the neural policy is active or an ALERT/ESCAPE saccade is
> running. In those ticks the target reverts to `baseline_speed` (9 BL/s). This matches
> the M1.8-R0 observation that WORLD can replace ecological speed targets with the
> baseline target. It is documented here rather than silently activated, and a regression
> test pins the behavior.

**Excluded — frozen M1.8-A lifecycle:** `LAND_APPROACH` and both takeoff paths. The
legacy `LAND_OR_PERCH` ecological state remains disabled while the lifecycle is active.

## 10. Calibration transfer

Adding a config key changes the canonical config hash, so provenance correctly failed
closed and a new transfer record was required — exactly as in M1.8-A.

`results/game/calibration_room_m1_8_b2a.json` resolves to threshold **1.45** and records
the full chain: source `calibration_room_m1_8_a.json` with its SHA256, plus
`original_measurement` pointing at `calibration_room_m1_7_1.json` with its SHA256, so the
provenance of the single underlying fixed-fly-v2 measurement stays traceable through two
transfers. `changed_config_paths` is exactly
`["kinematics", "config_version", "policy.calibration_paths"]`.

No recalibration was performed and none is justified: fixed-fly-v2 disables ecology,
lifecycle, fly motion and collisions, and `room_kinematic_scale` at 1.0 is a no-op on a
path that protocol does not exercise. The existing paired fixed-fly regression still
asserts bit-identical DNp01 arrays against the pre-M1.8-A config.

Provenance still fails closed: perturbing `brain.gain`, `encoder.encoder_seed`,
`lifecycle.contact_speed_bl_s` **or now `kinematics.room_kinematic_scale`** makes
resolution raise `No matching ...`.

`config_version` 10 -> 11.

## 3. Lifecycle architecture

Each fixed 20-ms tick evaluates the real visual/neural pathway first, then ecology,
then the local lifecycle, then WORLD physics.

```text
AIRBORNE -> LAND_APPROACH (ORIENT -> DECELERATE -> LEG_COMMIT)
         -> physical swept contact -> TOUCHDOWN -> PERCHED [optional FEEDING]
         -> TAKEOFF_VOLUNTARY -> AIRBORNE
PERCHED       + nonzero neural Action.escape -> TAKEOFF_ESCAPE -> AIRBORNE/ESCAPE
LAND_APPROACH + neural ESCAPE                -> abort -> neural airborne escape
LAND_APPROACH + cue loss / recession / timeout -> abort / fly-by -> AIRBORNE
```

Arbitration rule, verified by test: **ESCAPE interrupts landing; ALERT alone never
fabricates a takeoff action.** ALERT suppresses new approach eligibility and voluntary
departure accrual, but does not launch a perched fly and does not synthesize an escape
direction or magnitude.

Information boundary. `LandingSense` carries only `affordance`, `bearing`,
`angular_extent`, `angular_expansion`, `odor`, `contact`, `food_contact`. No source
coordinates, surface identity, nearest-surface world vector, destination, pointer or
swatter state reaches the controller. Its `MotionState` is an explicit local copy with
translational speeds converted to BL/s; the neural `MotionState` and the policy
observation whitelist are unchanged. `LifecycleController.step` rejects any object that
is not exactly `LandingSense` / `MotionState` / `ThreatState`.

Audited directly from the recorded sessions, with the same assertions now in the test
suite: every `policy_observations.jsonl` row across the 1200/340/120-tick recordings
contains exactly `{neural, motion, behavior_state, history}`, and none of
`lifecycle, contact, surface, landing, affordance, odor, food, perch, angular_extent,
angular_expansion, swatter, pointer` appears anywhere in the serialized observations.
The same privileged state **is** retained in `ticks.jsonl` (`lifecycle` block,
`room_world.contact_pose`) for offline WORLD analysis.

## 4. Landing pipeline

Multi-stage and evidence-driven, not `timer expires -> land`:

1. **Eligibility.** Strongest forward visible landable disk, affordance >= 0.075,
   bearing within 65 degrees, positive angular expansion, threat CALM, no retry
   cooldown, sustained for 0.12 s. Verified: a single frame does not enter approach.
2. **Orientation.** Bounded proportional steering on retinal bearing, capped at
   1.5 rad/s.
3. **Deceleration.** With `q = theta/60deg + max(0, theta_dot) * 0.35 s`, the requested
   speed is `max(1.5 BL/s, measured_speed / (1 + q*q))`. Verified monotone in all three
   inputs: larger extent decelerates more, larger expansion decelerates more, higher
   measured speed yields a higher request.
4. **Leg commitment.** Separate gate requiring extent >= 60 degrees **and** bearing
   within 20 degrees **and** speed <= 6 BL/s. Verified: fast or misaligned approaches do
   not commit.
5. **Physical touchdown.** WORLD-side swept outside-to-inside disk intersection, only
   while committed and at <= 3 BL/s.

Angular geometry is exact: `theta = 2 asin(r/d)`, with the analytic derivative
`theta_dot = 2*r*v_closing / (d * sqrt(d*d - r*r))`. A test confirms the analytic
expansion matches a finite difference of the extent to 5 decimal places, and that pure
rotation changes bearing but **not** expansion. The legacy
`EcologicalSense.surface_expansion` is not reused as true angular expansion.

Elapsed time never causes contact: a controller held at maximum affordance with zero
expansion for 100 ticks stays AIRBORNE, and `touchdown()` raises unless the approach is
committed.

## 5. Land versus fly-by

Not every valid approach lands. Three distinct abort paths are exercised:

| Outcome | Trigger | Evidence |
| --- | --- | --- |
| Fly-by / cue loss | recession or loss of visibility for 0.16 s | unit test + oblique fixture |
| Safety timeout | approach exceeds 10 s | unit test |
| Neural abort | real `Action.escape` from the frozen brain | real-neural scenario |

Deterministic oblique fly-by fixture (`Fly(1220, 1190, -600, 0, pi)`, seed 101):
approach onset tick 5, commit tick 57, then `approach_abort / fly_by_or_cue_loss` at
tick 141 — a committed approach that still did not capture. Aborts increment
`failed_approaches` and impose a 4 s retry cooldown.

A capture-speed guard (`touchdown_max_speed_bl_s` 3.0) means a fast committed pass
crosses the non-solid disk instead of attaching.

## 6. Touchdown and contact semantics

- Contact is the **earliest** swept intersection of the fly disk with a landable disk.
  Verified: a 500-unit single-step sweep from x=1400 to x=800 stops exactly at
  x=1126 (the surface edge) instead of tunneling through.
- **No snap-back.** An already-overlapping pass returns no contact and leaves the
  position untouched (verified: `Fly(1030, ...)` from `(1040, ...)` returns `None`,
  x stays 1030).
- On contact, velocity, yaw rate and applied target speed are set to zero in the same
  tick, and `contact_pose = (x, y, heading)` is latched.
- While stationary, WORLD restores the latched pose every tick, resets the saccade
  actuator, and returns before ordinary flight integration — the airborne controller
  cannot push the fly. Verified over 75 ticks: position, heading, velocity and yaw rate
  are bit-identical, `saccades.kind == 'NONE'`, and the flight clock and wait timer do
  not advance.
- The ordinary strike collision path still runs, so a perched fly remains hittable.

## 7. Perch behavior

PERCHED is a living state, not sleep and not death:

- `fly.alive` stays true; the renderer draws folded wings plus a green contact ring,
  distinct from the splat state.
- Translational speed is exactly 0.
- Ecology keeps updating: over a 240-tick natural ROOM session the perched fly's odor
  reading varies (non-zero peak-to-peak) and the DNp01 readout varies, confirming that
  local sensing and the MaleCNS pathway remain live while attached.
- The HUD shows effective lifecycle state and motion first, then the ecological
  command explicitly labelled as an unexecuted intent (section 18). The render capture
  shows ecology still *requesting* 11.4 BL/s while the applied drive is 0.0 BL/s.
- Verified that a commanded airborne turn plus saccade under ALERT changes neither
  heading nor speed while perched.

## 9. Voluntary versus neural escape takeoff

**Voluntary** departure is a seeded unit-exponential hazard, not a countdown:

```text
rate = 0.12 * (1 + dwell/12 s) / (1 + 0.5 * odor)
rate *= 0.45   # only with food contact and sufficient odor
```

Hazard accrues only on CALM ticks and only after the 2 s minimum dwell; dwell itself
always advances. Verified: identical seed and conditions give an identical departure
tick; changing food/odor context with the **same** seed and dwell changes the departure
tick (later with feeding); a different seed gives a different tick; departure never
occurs before the minimum dwell. Launch applies a one-tick 6 BL/s initial condition
along the retained contact heading.

**Escape** takeoff requires a genuine nonzero `Action.escape` from the frozen policy. It
detaches and then uses the unchanged direction-normalized
`escape_impulse * Action.strength` path (verified exactly `880 * 0.5 / 24` BL/s for
strength 0.5). A zero-strength escape action cannot launch a perched fly.

Measured separation in the recorded scenarios:

| Scenario | Launch | Tick | DNp01 total at launch | Threshold |
| --- | --- | --- | --- | --- |
| voluntary | `voluntary_takeoff` | 913 | **0.000124** | 1.45 |
| perched_threat | `escape_takeoff` | 265 | **1.510** | 1.45 |

The voluntary launch occurs with the threat readout four orders of magnitude below
threshold; the escape launch occurs on a tick where the real readout crosses it.

**No click, no proximity shortcut.** All three scenarios recorded `strikes: 0`. The
perched-threat scenario only moves the physical paddle toward the fly. The abort trace
shows the full causal chain:

```text
tick 54  DNp01 0.929  retina theta_dot 0.371  escape False  LAND_APPROACH
tick 55  DNp01 0.761  retina theta_dot 0.386  escape False  LAND_APPROACH
tick 56  DNp01 1.623  retina theta_dot 0.401  escape True   AIRBORNE   <- approach_abort / neural_escape
tick 57  DNp01 1.329  retina theta_dot 0.360  escape False  AIRBORNE
```

Rising retinal expansion from the physical paddle drives LC4/LPLC2 stimulation into the
frozen MaleCNS graph; the DNp01 readout crosses 1.45; only then does the lifecycle react.

## 16. Known limitations

1. **Sub-timestep takeoff dynamics are not explicitly resolved.** The main timestep is
   20 ms; the ~2 ms biomechanical takeoff is coarse-grained into a macroscopic initial
   condition. No millisecond biomechanical fidelity is implied.
2. The model is a horizontal 2-D slice. Takeoff is "lifting out of support"; no vertical
   wing or leg trajectory is computed. A launch can therefore fly across the non-solid
   landing disk after detaching.
3. Landing cues use an ideal geometric disk projection: no occlusion reconstruction, no
   noisy depth estimator, no identified visual landing circuit.
4. Landing, perching, feeding and voluntary departure are phenomenological controllers,
   not neural circuits. No value in section 10 is class A.
5. Feeding is a labelled contact overlay. No metabolism, hunger, ingestion amount, meal
   duration or feeding microstructure is modelled.
6. Only the two configured non-solid disks are landable. Walls, the solid column and the
   ceiling are not perchable.
7. Lifecycle metrics are simulator descriptives, not activity-budget estimates. Null
   medians mean "no complete eligible bout", not zero duration; short scenarios report
   `median_flight_bout_seconds: null`.
8. TOUCHDOWN and TAKEOFF occupy one tick each as event labels, not measured phase
   durations.
9. Contact velocity is constrained to zero at the intersection; leg compliance, adhesion
   and post-landing grooming are not modelled.
10. No activity budget, flight-speed distribution, RL or personalized learning is
    included; those remain out of scope for M1.8-A.

## 17. Manual human playtest procedure

Both sessions record to `results/game/sessions/<session_id>/` (git-ignored).

### A. Passive ecology session (5-10 minutes, do not attack)

```powershell
Set-Location D:\Projects\flybrain-lab
& .\.venv\Scripts\python.exe -m game.app --arena room --seed 255 --record --windowed
```

Keep the mouse pointer far from the fly and **do not click**. Press `H` to show the
neural/mode HUD. Expected observations, without moving the fly manually:

1. Free flight with saccades, then a visibly *decelerating* approach toward the
   fermentation source (HUD: `LAND_APPROACH / ORIENT`, then `DECELERATE`, then
   `LEG_COMMIT`).
2. Physical touchdown at roughly 2.6 s of simulated time for this seed. The HUD switches
   to `LIFECYCLE PERCHED / CONTACT`; the fly is drawn with folded wings inside a green
   ring; `MOTION` goes to `0.0 BL/s` while `ECO INTENT` stays non-zero and is explicitly
   marked `not executed: suppressed while perched`.
3. An amber ring and a `FEEDING` label appear on the fly shortly after touchdown on the
   fermentation source, and `FEEDING` is appended to the `LIFECYCLE` row.
4. A **voluntary** takeoff later (near 18 s for this seed) with no threat present, and a
   return to ordinary flight.
5. Some approaches should abort as fly-bys rather than landing.

To confirm a perch on a **non-food** surface, watch for a landing on the small disk on
the right of the room; `FEEDING` must **not** appear there.

### B. Threat-while-perched session (no clicking)

The first human passive playtest (session `20260921T173503.854443Z-44889dbb`) confirmed
the lifecycle works. Two perches were recorded:

| Perch | Touchdown | Feed start | Voluntary takeoff | Feeding duration |
| --- | --- | --- | --- | --- |
| 1 | 2.56 s | 2.58 s | 18.22 s | ~15.64 s |
| 2 | 164.14 s | 164.16 s | 184.54 s | ~20.38 s |

Events: 3 approach onsets, 2 commits, 1 abort, 2 touchdowns, 2 voluntary takeoffs, 0
escape takeoffs. Alive fractions: perched ~12.65%, feeding ~12.64%.

**No lifecycle logic defect was found.** The reported problem was presentation: while
physically perched and feeding, the HUD still prominently showed the background
ecological controller state (`ODOR_TRACK`) requesting non-zero flight speed, so the
tester believed the fly was still auto-tracking and that feeding never happened. The
legacy top-level `landing_attempts` also read 0 despite 3 approach onsets and 2
touchdowns, because the lifecycle disables the legacy LAND_OR_PERCH timer.

The correction is presentation and reporting only. **No landing timing, feeding timing,
voluntary takeoff, ecology, swatter or neural threshold was touched** — re-running
`tools/lifecycle_sanity.py` afterwards produced identical event counts and identical
exact replays (1200/340/120 ticks).

1. **HUD ordering.** Effective physical behavior is now primary, with the ecological
   command labelled as an unexecuted intent:

   ```text
   LIFECYCLE  PERCHED / CONTACT / FEEDING
   MOTION     0.0 BL/s  applied drive 0.0 BL/s
   ECO INTENT ODOR_TRACK  requested 11.4 BL/s
              not executed: suppressed while perched
   ```

   The suppression reason is derived from the kinematic profile WORLD **actually
   applied**, not from the mode alone, so it is accurate for perching
   (`stationary_contact`), touchdown, landing approach, voluntary launch and neural
   escape override. When ordinary flight executes the ecological command, no
   suppression row is shown. Legacy LAB/GAME arenas keep their original HUD rows.

2. **Feeding visibility.** A perched, feeding fly is drawn with an amber ring and an
   amber `FEEDING` label on a dark backing plate, distinct from the green perch ring and
   visible with the neural HUD switched off. This is state visualization only: no
   proboscis mechanics, ingestion model or feeding animation is implied.

3. **Reporting.** When the lifecycle is active, `summary.json` gains
   `landing_attempts_status` explaining that the legacy counter is a disabled ecology
   timer and not the M1.8 landing count, and `REPORT.md` now leads with an authoritative
   lifecycle line (approach onsets, commits, aborts, touchdowns, both takeoff causes and
   alive airborne/perched/feeding fractions) placed **before** the relabelled legacy
   counter. The legacy scalar is retained for continuity with schema-3 sessions.

Six regression tests were added (`TestLifecyclePresentation`): FEEDING shown while
ecology still reports `ODOR_TRACK`; motion and applied drive both zero while perched;
airborne intent not labelled suppressed; legacy arenas unchanged; the report not
presenting the legacy counter as the lifecycle landing count; and every HUD behavior row
fitting inside the fixed-width neural panel. That last test was added because the first
attempt at this fix overflowed the panel and clipped the suppression note off-screen.

Historical session files were not modified.

## 20. Acceptance and freeze

M1.8-A passed both human acceptance playtests and is committed. The following are
**frozen** unless new recorded evidence exposes a real defect, and must not be retuned
merely to change game difficulty:

- landing pipeline
- touchdown and contact mechanics
- perched physical state
- feeding presentation overlay
- voluntary takeoff path
- neural escape takeoff path
- lifecycle recorder schema
- lifecycle/policy data isolation

M1.8-B, activity budgets, context-dependent flight-speed distributions and RL are not
implemented and remain out of scope.
